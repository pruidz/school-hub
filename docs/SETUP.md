# გაშვება — შენი სამი ნაბიჯი

ყველაფერი დანარჩენი უკვე გაკეთებულია. `.env.local` შექმნილია, საიდუმლო გასაღები
დაგენერირებულია, მთელი ბაზა ერთ ფაილშია შეკრებილი, შემმოწმებელი სკრიპტი დაწერილია.

შენ სამი რამ გჭირდება: **ანგარიში, სამი გასაღები, ერთი დაწკაპუნება.** ~10 წუთი.

---

## ნაბიჯი 1 — Supabase პროექტი

1. https://supabase.com → **Start your project** → დარეგისტრირდი (GitHub ან email). უფასოა.
2. **New project**:
   - **Name:** `school-hub`
   - **Database Password:** დააჭირე „Generate" და **შეინახე პაროლის მენეჯერში**.
     ეს ბაზის პაროლია — აპლიკაციაში შესვლისთვის არ გამოგადგება, მაგრამ დაკარგვა არ ღირს.
   - **Region:** `Central EU (Frankfurt)` — საქართველოდან ყველაზე ახლოა
   - **Plan:** Free
3. დაელოდე ~2 წუთს.

---

## ნაბიჯი 2 — სამი გასაღები

Supabase-ში: **Project Settings → API**. სამი მნიშვნელობა გჭირდება.

გახსენი პროექტის ფესვში ფაილი **`.env.local`** (უკვე არსებობს) და შეავსე პირველი სამი ხაზი:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGci...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGci...
```

| სად წერია Supabase-ში | რომელ ხაზში |
|---|---|
| **Project URL** | `NEXT_PUBLIC_SUPABASE_URL` |
| **anon** `public` | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| **service_role** `secret` | `SUPABASE_SERVICE_ROLE_KEY` |

დანარჩენი ორი ხაზი უკვე შევსებულია — ხელი არ ახლო.

⚠️ `service_role` გასაღები არასდროს გააზიარო და არსად ჩასვა ბრაუზერის კოდში.
ის ბაზის ყველა შეზღუდვას გვერდს უვლის. `.env.local` git-ში არ ხვდება.

---

## ნაბიჯი 3 — ბაზის აწყობა (ერთი დაწკაპუნება)

1. Supabase-ში გახსენი **SQL Editor** → **New query**
2. გახსენი ფაილი **`supabase/APPLY_ALL.sql`**, მონიშნე ყველაფერი, დააკოპირე
3. ჩასვი რედაქტორში და დააჭირე **Run**

ერთი ფაილი, ერთი გაშვება. ყველა 11 მიგრაცია ერთ ტრანზაქციაშია — თუ რამე ჩავარდა,
არაფერი გაკეთდება ნახევრად და უბრალოდ თავიდან ცდი.

წარმატებული გაშვების შემდეგ უნდა გქონდეს: **17 ცხრილი, 1 ხედი, 59 წესი, 37 ფუნქცია.**

```bash
npm run doctor
```

ეუბნება ნამდვილ პროექტს იმ კითხვებს, რაც პირველი გაშვებისას ჩვეულებრივ ცდება:
გასაღებები ადგილზეა თუ გადანაცვლებული, ყველა მიგრაცია გაშვებულია თუ არა, საცავი
დახურულია თუ საჯარო, და — ყველაზე მთავარი — **გაუვლელი მომხმარებელი მართლა ვერ
კითხულობს თუ არა ცხრილებს.**

თუ ყველგან მწვანე ✓ არის:

```bash
npm run dev
```

გახსენი http://localhost:3000 და გააკეთე მშობლის ანგარიში.

## მოგვიანებით — ინტერნეტში ატანა

1. პროექტი აიტვირთოს GitHub-ზე, **პრივატ** რეპოზიტორიაში
2. https://vercel.com → **Import Git Repository**
3. **Environment Variables** — ჩასვი `.env.local`-ის **ხუთივე** ცვლადი
   (`CHILD_AUTH_SECRET`-ის ჩათვლით — მის გარეშე ბავშვის ლოგინი საერთოდ არ იმუშავებს),
   ოღონდ `NEXT_PUBLIC_SITE_URL` შეცვალე Vercel-ის მისამართით
4. Supabase → **Authentication → URL Configuration** → **Site URL** და
   **Redirect URLs** დაამატე Vercel-ის მისამართი
5. Deploy

ამის შემდეგ ბავშვი ტელეფონში გახსნის მისამართს, გააკეთებს „Add to Home Screen"
და აპლიკაციასავით გამოიყენებს.
