# პირველი გაშვების შემოწმება

გაიარე ეს სია მას შემდეგ, რაც [SETUP.md](SETUP.md)-ის 1–5 ნაბიჯს შეასრულებ და **სანამ**
ნამდვილ მონაცემებს შეიყვან.

მიგრაციები გაუშვი **ზუსტად ამ თანმიმდევრობით**: `0001 → 0002 → … → 0008`.
`0007` და `0008` აუცილებელია — ისინი ხურავს ხვრელებს, რომლებსაც `0004` ტოვებს.
თუ `0007`-ს გამოტოვებ, ინტერფეისში ვერაფერს შეამჩნევ, მაგრამ ცნობისმოყვარე ბავშვი
მთელ ოჯახის მონაცემს დაეუფლება — ეს გაზომილია, არა ნავარაუდევი.

## ბ. უსაფრთხოების მიღება

**ამ სიის უმეტესობა უკვე ავტომატურად მოწმდება.** ლოკალურად აეშვება ნამდვილი Postgres,
დაედება ყველა მიგრაცია და თავს დაესხმება სქემას ოთხი მხრიდან (გაუვლელი მომხმარებელი,
ბავშვი, მშობელი, სისტემა). 132 ტესტი. გაშვება:

```bash
npm run test:db
```

ტესტები შემოწმებულია „მუტაციით" — განზრახ დაბრუნდა ძველი, დაუცველი ვერსია და
რვიდან ექვსი შეტევა ისევ გაიარა, ანუ ტესტები ნამდვილად იჭერენ. თუ მომავალში ვინმემ
(მე ჩათვლით) უსაფრთხოების წესი გააფუჭოს, `npm run test:db` ჩავარდება.

ქვემოთ დარჩა მხოლოდ ის, რაც **მხოლოდ ნამდვილ Supabase-ზე** შემოწმდება — რადგან
ლოგიკა ბაზაში კი არა, სერვერის კოდშია.

- [ ] **PIN-ის ბლოკი.** 5 არასწორი PIN → 15 წუთით იბლოკება. ბავშვმა ვერ უნდა მოხსნას;
      **მშობელმა** — `/parent/children`-იდან — უნდა შეძლოს
- [ ] **მოწვევის კოდის ხელახლა გამოყენება.** ერთხელ გამოყენებული კოდი მეორედ არ
      უნდა მუშაობდეს
- [ ] **ფაილის ზომა და ტიპი.** სცადე ძალიან დიდი ფაილის და არა-სურათის ატვირთვა
- [ ] **ფოტოს ბმული.** დააკოპირე ფოტოს ბმული და გახსენი 4 საათის შემდეგ →
      აღარ უნდა იხსნებოდეს

### ხელით გასავლელი (სურვილისამებრ, დამატებითი დარწმუნებისთვის)

ქვემოთ ჩამოთვლილი უკვე ავტომატურად მოწმდება, მაგრამ თუ საკუთარი თვალით გინდა:

დაამატე **ორი** ბავშვი, ორივეს გაუკეთე ლოგინი. ორივეს ჰქონდეს დავალებები.
ყველა შემოწმება ხდება **პირველი ბავშვის** სესიით. ყველგან პასუხი უნდა იყოს „არა".

- [ ] **1. მეორე ბავშვის მონაცემი ჩანს?** პირველი ბავშვის ლოგინით სცადე მეორის
      დავალების მისამართის პირდაპირ გახსნა (`/kid/assignments/<მეორის id>`) → უნდა
      დაბლოკოს
- [ ] **2. საკუთარი თავის მშობლად გამოცხადება.** ბავშვის სესიით, ბრაუზერის კონსოლში:
      ```js
      const { createClient } = await import('@supabase/supabase-js');
      ```
      მარტივი გზა: გახსენი Network ჩანართი, იპოვე PostgREST-ის მოთხოვნა და გაიმეორე
      `profiles` ცხრილზე `role: 'parent'`-ით → უნდა დაბრუნდეს შეცდომა
- [ ] **3. საკუთარი დავალების დადასტურება.** ბავშვი ვერ უნდა ახერხებდეს სტატუსის
      `approved`-ზე გადაყვანას
- [ ] **4. ვადის შეცვლა.** ბავშვი ვერ უნდა ცვლიდეს დავალების ვადას ან ტექსტს
- [ ] **6. სხვისი ფოტოს ნახვა.** დააკოპირე მეორე ბავშვის ფოტოს მისამართი და გახსენი
      პირველი ბავშვის სესიით → უნდა უარყოს

თუ რომელიმე გამოვიდა — **გამაჩერე და მითხარი**. ნამდვილ მონაცემებს ამის გარეშე ნუ
შეიყვან.
